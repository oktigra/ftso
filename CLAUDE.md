# CLAUDE.md — сайт ФТСО (ftso67.ru)

Этот файл Claude читает при каждом запуске. Здесь всё, что нужно, чтобы продолжить
работу без памяти чата. Знания о проекте живут в этом репозитории, а не в памяти Claude.

## Что это за сайт

- **ftso67.ru** — сайт Федерации тенниса Смоленской области (РФСОО «ФТСО»).
- Рабочий продакшен-сайт: публичная часть, админка, личный кабинет игроков,
  рейтинговый движок, заявки на турниры, сетки, галерея, документы, почта,
  юридическая часть по 152-ФЗ.
- Сайт достался Алексу от прежнего исполнителя. Тот ничего не передавал, нашёлся
  только этот репозиторий. Записи прежнего периода (до 07.10.2026) —
  `NEXT_CHAT_START.md`, `BACKLOG.md`, `COMPLIANCE.md`, `sessions/`. Там владелец
  называется «Олег».

## Стек

- Node.js + Express, свой код (не CMS). Шаблоны — `site/views`, сервер —
  `site/server` (`routes`, `lib`, `middleware`), миграции — `site/db`.
- База — SQLite (`better-sqlite3`).
- **Node 22.** На Node 24 модуль базы не собирается. В `package.json` указано
  `>=20`, но работаем на 22, как на сервере.
- `site/` и `rating/` лежат рядом намеренно: `site/` импортирует движок
  относительными путями. Не переносить `site/` в корень.
- Все команды — из `site/`:
  ```
  cd site && npm ci && cp .env.example .env   # секреты — любые случайные строки
  npm run migrate && npm run seed && npm start
  npm run accept                               # приёмка на временной базе
  ```
- Приёмка на 11.10.2026: **271 из 271**. Браузерным проверкам нужны Chromium,
  системные библиотеки и шрифты; путь к браузеру берётся из переменной окружения.

## Как устроен выкат

- **`main` — это боевой сайт.** Сервер сайта раз в 2 минуты сам забирает
  `origin/main` (`deploy/deploy-watch.sh`): `npm install`, `npm run migrate`,
  перезапуск, проверка ответа `/`. Перед каждым выкатом он копирует базу, а если
  новая версия не поднялась, сам возвращает старую.
- Защиты ветки `main` на GitHub нет. Любой пуш в `main` сразу уходит в прод.
- Новые страницы проверка `/` не ловит: после выката проверять их снаружи самому.

## Правила Алекса (обязательны)

1. **Никаких патчей.** Код меняется сразу и полностью, по-настоящему, без заплаток
   и обходов.
2. **Перед каждым изменением боевого сайта — точка отката. Это закон.** Перед
   слиянием в `main` ставится метка на текущую боевую версию:
   `rollback/<ГГГГ-ММ-ДД>-before-<что>`. Список меток — в
   [`docs/claude/state.md`](docs/claude/state.md).
3. **Порядок работы:** ветка → правка кода → тесты в приёмке → полный прогон →
   скриншоты «было/станет» → PR. Перед выкатом показать Алексу, как будет выглядеть
   сайт.
4. **В `main` не пушить никогда.** Только ветка и PR. Сливать — только после явного
   «да» Алекса на это слияние.
5. **Если Алекс дал несколько задач, делать все вместе.** Не откладывать молча
   ни одну из них.
6. **Инструменты ставятся постоянно**, туда, где с ними удобно работать, а не во
   временные папки.
7. Алекс не хочет подтверждать разрешения: всё принимается по умолчанию.
8. **Репозиторий публичный.** Сюда не пишутся пароли, токены, ключи, IP и адреса
   серверов, номера аккаунтов хостинга, личные почты и персональные данные.

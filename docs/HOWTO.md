# Как внести правку в сайт ftso67.ru и выложить её

Инструкция для человека или любого ИИ-помощника. Ничего не требует, кроме доступа к этому
репозиторию на GitHub и (для проверки у себя) компьютера с Node.js 22.

## Как изменения попадают на сайт

Сервер сайта **сам** раз в 2 минуты забирает ветку `main` с GitHub: ставит зависимости,
обновляет базу (миграции), перезапускается и проверяет, что сайт отвечает. Перед каждым
выкатом он копирует базу, а если новая версия не поднялась — сам возвращает старую.

Поэтому **слияние в `main` = выкат на боевой сайт** через 1–2 минуты. Свой компьютер для
выкладки не нужен.

## Порядок работы

1. **Ветка.** Новую ветку от `main` (на GitHub: кнопка выбора ветки → ввести имя, например
   `fix/ошибка-в-заявке`). В `main` напрямую не писать.
2. **Правка.** Изменить файлы в ветке — на своём компьютере или прямо на GitHub
   (кнопка ✏️ у файла → «Commit changes» в эту ветку).
3. **Проверка у себя** (желательно, если правка в коде):
   ```bash
   cd site && npm ci && cp .env.example .env
   npm run migrate && npm run seed && npm start   # сайт на http://127.0.0.1:3000
   npm run accept                                  # приёмка, должна быть вся зелёная
   ```
4. **PR.** На GitHub: «Compare & pull request» → описать, что и зачем изменено, приложить
   скриншоты «было/станет».
5. **Согласие владельца.** Сливать только после его явного «да».
6. **Точка отката перед слиянием.** На GitHub: выбрать ветку `main` → в поле веток ввести
   `rollback/ГГГГ-ММ-ДД-before-<что>` → «Create branch … from main».
7. **Слияние.** В PR — «Merge pull request». Через 1–2 минуты правка на сайте.
8. **Проверка на сайте.** Открыть изменённые страницы на ftso67.ru (на компьютере и
   телефоне). Сервер сам проверяет только главную `/` — новые страницы смотреть руками.

## Если что-то сломалось

- Если новая версия не поднялась, сервер откатится сам.
- Если сайт работает, но правка вредная: на GitHub открыть PR, нажать **«Revert»** — получится
  PR, отменяющий изменения; слить его, через 1–2 минуты сайт вернётся.
- Или вернуть `main` к точке отката (ветка `rollback/...`) — это делает тот, у кого есть
  права администратора репозитория.

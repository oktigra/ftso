# Рейтинговый движок ФТСО

Рейтинг Федерации тенниса Смоленской области (ftso67.ru). Node, чистый
JavaScript (ES-модуль), без фреймворков, без БД, без внешних зависимостей.
Чистые функции над данными в памяти. Каталог самодостаточен — переносится
целиком.

## Запуск

```
node rating/rating.test.mjs   # тестовый харнесс, 30 проверок
node rating/example.mjs       # пример: печать таблицы + CSV/JSON в rating/out/
```

## Файлы

- `rating.mjs` — расчёт: очки, окно, тай-брейк, ранги.
- `export.mjs` — печать таблицей, CSV (с BOM для Excel), JSON.
- `rating.test.mjs` — выдуманные данные и посчитанный вручную ожидаемый результат.
- `example.mjs` — пример сезона.

## Что считается

Очки за турнир = очки по месту × коэффициент категории. Очки по месту — из
первой записи `pointsByPlace`, у которой `maxPlace >= place`; нет такой записи
(место дальше таблицы) → `pointsBeyondTable`. Рейтинг игрока = сумма
`countBest` (6) лучших турниров за окно `windowDays` (364 дня) назад от `asOf`.

Окно: `0 <= (asOf − endDate в днях) < windowDays`. Даты разбираются вручную
(`Date.UTC` от чисел, не от строки), `asOf` по умолчанию — сегодня по UTC.

## Конфиг — данные, меняются без кода

```js
{
  pointsByPlace: [ { maxPlace: 1, points: 100 }, ... ],  // по maxPlace ПО ВОЗРАСТАНИЮ
  pointsBeyondTable: 0,
  categoryCoef: { A: 2, B: 1 },   // A — чемпионаты и первенства области, B — остальные
  countBest: 6,
  windowDays: 364,
  ratingStatus: 'preliminary',    // вручную: первый год предварительный, потом 'final'
}
```

`ratingStatus` — только метка, на расчёт не влияет; движок прокидывает её в вывод.

## Вход

```js
computeStandings({
  tournaments,   // [{ id, name, endDate: "YYYY-MM-DD", category: "A" | "B" }]
  results,       // [{ playerId, playerName, tournamentId, place }]  place — целое с 1
  matches,       // необязательно: [{ tournamentId, winnerPlayerId, loserPlayerId }]
  asOf,          // необязательно, по умолчанию сегодня по UTC
  config,        // необязательно, по умолчанию DEFAULT_CONFIG
})
```

`computeStandingsByAgeGroup({ ...то же, players: [{ playerId, ageGroup }] })` —
тот же расчёт внутри каждой возрастной группы.

## Целостность данных — движок падает, а не молчит

- `place` не целое или < 1 → падение (верхней границы нет: место дальше
  таблицы даёт `pointsBeyondTable`);
- пара (`playerId`, `tournamentId`) в `results` не уникальна → падение;
- `tournamentId` в `results` или `matches`, которого нет в `tournaments`, →
  падение (молча потерять результат = занизить рейтинг);
- разные имена у одного `playerId` → ПРЕДУПРЕЖДЕНИЕ, берётся первое
  встреченное; идентификатор — `playerId`, имя только для показа.

## Тай-брейк при равных очках — каскад на группе

1. **Личные встречи**, рекурсивно. Учитываются все матчи турниров в окне —
   независимо от того, вошёл ли турнир в зачётные 6 и есть ли у игроков
   результат в нём. Метрика — победы над членами ТЕКУЩЕЙ подгруппы; при делении
   подгруппы победы пересчитываются с нуля. Не разделило (настоящий цикл) →
   блок целиком на ступень 2. Нет `matches` — ступень пропускается.
2. **Места на турнирах** — по зачётным (`counted`), отсортированным по очкам
   за турнир по убыванию, позиция за позицией; на первой различающейся выше
   тот, у кого больше. Недостающая позиция = 0.
3. **Количество сыгранных турниров** в окне (`totalInWindow`).
4. Всё совпало → делят место (shared rank), следующий блок получает ранг с
   пропуском.

Каждая ступень — отдельная запись в `TIEBREAK_STAGES`; докрутить или
переставить — правка списка.

## Выход

```js
{ ratingStatus, asOf, warnings, players: [
  { rank, playerId, playerName, ratingPoints,
    counted: [{ tournamentId, name, category, place, points }],  // до 6
    totalInWindow }
]}
```
